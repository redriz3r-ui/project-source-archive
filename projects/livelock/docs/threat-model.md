# Threat model — v0.2.0

Goal: restrict navigation in this Chrome profile while protection is enabled. The user can disable/uninstall the extension. It is not a commitment lock, parental control, OS-wide filter or guarantee of instantaneous relocking.

Untrusted inputs: handle/URL/domain text, stored schema, remote API JSON, content-script messages and page navigation. Parsers reject wildcards, credentials/ports in room URLs, lookalike domains, unsupported Unicode/IDN, reserved routes and malformed configuration. Accepted handles remain a conservative 3–30 ASCII subset; official API documents a room-username field max of 111 characters but not complete naming rules.

UI control messages require the extension's own ID and exact popup/options sender document URL. Content guards receive a background decision based on sender URL, never a page-supplied allow URL. Allow rules always derive from the locally selected exact handle. Remote metadata cannot supply arbitrary URLs or executable code.

Connected provider: fixed HTTPS official Users Online v2 endpoint and documented parameters. Public affiliate campaign identifier is not a secret. No cookies/credentials, redirects, arbitrary host or stream requests. The user's requesting IP preserves documented geo restrictions. Full paginated payloads are processed transiently, with only the selected exact public match retained. Missing/non-public/malformed/failed/limited status is UNKNOWN. A public result is trusted only from this fixed origin's fresh JSON response; source-event freshness is not independently available, and HTTP Date is only transport freshness. Opt-out, roster movement and regional filtering prevent absence from proving OFFLINE.

Budgets persist in session storage (60-second minimum scan interval, bounded 40-page scan, overall timeout, short delays, Retry-After backoff). A cached exact-selected observation may be reused only within its original validity, never extended. A failed attempted refresh discards prior LIVE; it is not used as fallback. No full roster/history, login data or explicit content is persisted.

Serialized rule writes, config revision and request generation prevent stale responses superseding edits/Lock now. Revocation precedes state changes/relocking. Startup clears grants, restores configured denial and recreates alarms. ON always restores denial; OFF is an explicit acknowledged opt-out that removes static/dynamic/session enforcement.

Residuals: DNR allowances do not self-expire. Sleep/scheduling and missed events can delay lease removal. Document-start concealment and focus/visibility/250 ms SPA/expiry checks reduce exposure but cannot guarantee zero visible interval. Allowed pages may contain recommendation thumbnails/chat/content that is not sanitized. Only listed domains are filtered; incognito needs Chrome permission; other browsers/devices are excluded. Competing extensions can alter outcomes. Chrome API failures can prevent synchronization; reload and inspect the extension error panel if a control reports failure.

Privacy boundary: direct official API requests reveal requesting IP/public campaign to Chaturbate, not the selected handle as a query. No intermediary server is used. Full roster responses can include unrelated sensitive profile fields, but the client ignores/discards them and never follows their image/embed/video URLs. Broad public distribution remains gated on polling/license/rate-policy confirmation and operational/privacy review. The optional future gateway would require a new review and disclosure.

Version 0.3.0 uses a broad bundled community adult-domain snapshot. Data-only imports are validated and provenance hashed; no remote code or runtime list update is permitted. Protect shared/mixed-content roots from blanket category denial and apply narrow board rules instead. Classification errors, newly created domains and NSFW content on otherwise allowed services remain possible. This expands coverage without claiming content classification or complete protection.

Version 0.4.0 adds a strict ThePornDude domain overlay under the user’s explicit request. Listed domains override the earlier mixed-content exclusions and are blocked in full. Source collection is a data-preparation step only; no runtime crawler, added host permissions, copied review/media content or automatic source updates. See directory-blocklist.md.

Version 0.4.1 personalizes the top-level restricted page via a dedicated minimal read-only message. Background validation requires this extension’s ID, the exact blocked.html sender URL and frameId 0 before returning a handle. Embedded frames receive no selected handle, do not request personalized status and render generic copy. The restricted page is not added to the trusted popup/options control-message allowlist, uses textContent for the validated handle and never embeds it in its URL.

Version 0.4.2 allows the top-level restricted page to read its existing local config/manual-lock preference for a resilient name reminder. This is not a grant source: it always marks live verification unavailable until the background positively responds. Embedded rendering performs neither the storage read nor a status request and exposes no selection. No new Chrome permissions, remote requests or access-policy changes.
