The proposed **GPL-3.0-or-later** license remains feasible for original plugin code using the reviewed QGIS APIs. A GitHub `GPL-3.0` badge or generic license text does not by itself establish an “or later” grant. Check the actual program notices. [FSF compatibility guidance](https://www.gnu.org/licenses/gpl-faq.en.html#AllCompatibility).

## QGIS 4.2 / Qt6 practice and API checks

Use `qgis.PyQt`, Qt6 scoped enums and the installed QGIS API. Set `qgisMinimumVersion=4.2`, `hasProcessingProvider=yes`, and an explicit `qgisMaximumVersion=4.99` for the intended QGIS 4 family, with the actual tested versions disclosed. Do not use `supportsQt6`; it is obsolete. A version range controls discoverability, not proof of compatibility with every future 4.x release. [Official migration guidance](https://plugins.qgis.org/docs/migrate-qgis4).

The local probe imported `QgsProcessingAlgorithm`, `QgsProcessingProvider`, `QgsDockWidget` and `QgsVectorFileWriter.writeAsVectorFormatV3`, verified relevant methods and constructed a `QgsField` with `QMetaType.Type.QString`. It exercised native graph building/Dijkstra, `QgsDistanceArea` with explicit CRS and ellipsoid/unit conversion, and GeoPackage writing/reloading. It did **not** register five product algorithms, exercise a reviewer GUI, or install a ZIP. Those checks belong to the scaffold/integration gates.

The QGIS 4.2.3 [native director source](https://github.com/qgis/QGIS/blob/b041a18904a4dc9fdada8ecb2c84385054ddfee1/src/analysis/network/qgsvectorlayerdirector.cpp#L180) merges all line vertices within a tolerance, including interior vertices; even zero requested tolerance is clamped to `1e-10` in graph CRS coordinates. An X intersection without shared vertices stayed disconnected in our probe; adding coincident interior vertices made it connected. **“Does not automatically split crossings” is therefore insufficient to establish endpoint-only connectivity.** Do not use the director as our policy authority. Its source also catches a distance-transform exception after initializing distance to zero; our adapter must surface measurement failure rather than continue with zero length.

`QgsDistanceArea` can measure geographic geometry ellipsoidally and convert a planar projected-foot result into meters; both were verified. A scalar degrees-to-meters factor is unacceptable. A successful API probe does not establish the acceptable distortion of a chosen projected CRS or partial-edge fraction scheme; architecture must define those choices. `asPolyline()` conversion discarded Z/M in the probe, confirming the need for detection and explicit 2D handling before conversion.

For publication, current QGIS rules require documented usage, valid homepage/repository/tracker/license metadata, GPL-compatible licensing, no binaries and a package no larger than 25 MB. The source represented by the package must correspond to the public repository. [Publishing requirements](https://plugins.qgis.org/docs/publish). Uploaded versions undergo security scanning; critical findings prevent approval. That security process is separate from the informational Qt6 check and from our functional release gate. [Approval process](https://plugins.qgis.org/docs/approval). Recheck both policies at release.

## Architecture blockers and required closure

1. **Endpoint/transition semantics:** define exact endpoint equivalence in a declared graph CRS, explicit-junction membership, and directed edge-to-edge permissions. A node ID alone is insufficient for restrictions dependent on the arriving edge; use an expanded graph or `(node, incoming_edge)` search state. Reject implicit shared-interior-vertex connectivity. Require X, T, shared-interior-vertex and forbidden-turn fixtures.
2. **Snapping versus connectivity:** separate metric request attachment from graph connection tolerance. Define ties, edge eligibility, directed same-edge/reverse fractions, zero-distance requests and multiple requests on one edge. Never include an off-network connector as though it were an existing utility pathway; report snap offsets separately. A temporary snap cannot join separate edges.
3. **Measurement and supported geometry:** freeze CRS/ellipsoid/unit policy, transformation failure behavior, partial-edge length and shape reconstruction, multipart/curve/invalid-geometry treatment and Z/M detection. Specify rejection or an explicit 2D opt-in; no silent conversion. Define supported geographic extents and numerical tolerances in fixtures.
4. **Stable provenance and read-only inputs:** runtime layer IDs and provider FIDs alone are not durable across reload/export. Define source dataset identity, stable feature key or a versioned snapshot fallback, part/edge IDs, geometry fingerprints and stale-source behavior. Define review state tied to a route/config revision. No plugin may add UUIDs or commit edits into source layers to solve identity.
5. **Contract and evidence gates:** freeze versioned outputs, eligibility/unknown semantics, cancellation/partial-batch status and transactional export behavior. Declare and test one minimum QGIS 4.2 runtime plus release-platform coverage. Record this directory's lack of Git history before claiming reproducible source revisions. Direct source reuse remains blocked until its file-specific import record is approved; original implementation can proceed after the data contract resolves items 1–4.

These are design blockers for the upcoming architecture freeze, not evidence that the product is infeasible. The prioritized implementation risks and closure tests are in [RISKS.md](RISKS.md).
