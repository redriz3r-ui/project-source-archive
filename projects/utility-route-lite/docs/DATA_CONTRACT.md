# Utility Route Lite public data contract — `1.0.0`

Frozen 2026-10-16 for the QGIS 4.2+ plugin. [ARCHITECTURE.md](ARCHITECTURE.md) gives the rationale; [contract/v1.json](contract/v1.json) is the machine-readable registry of public IDs, enums, fields and Processing parameters. The prose here governs semantics if a registry comment is shorter. Network Builder now implements a subset; routing, review, batch and packaging are pending. Changes require a numbered decision and architect review under [DECISIONS.md](DECISIONS.md).

## Shared conventions

- All JSON files are UTF-8, no BOM, with `schema_version: "1.0.0"`. String keys use Unicode NFC. Stable identifiers use nonempty ASCII letters, digits, period, underscore and hyphen, maximum 64 characters, beginning with a letter or digit. `layer_key`, `profile_id`, `junction_id`, and caller supplied `route_id` follow this rule. `source_feature_key` is a unique, nonempty, NFC string up to 128 UTF-8 bytes from a declared source field. Duplicate feature keys in the line layer are a build error. Whitespace-only keys are invalid. No implicit QGIS FID fallback.
- JSON numbers must be finite; negative zero normalizes to zero. Geometries are 2D `[x,y]` arrays in declared CRSs. The graph/output CRS is projected and has meter horizontal units; the CRS is serialized as WKT2 plus its authority ID if available. Input `SOURCE_CRS` must match the source layer's declared CRS. `REQUEST_CRS` and the junction document's `junction_crs_wkt` are mandatory. Transform context and QGIS version are recorded. A missing/failed transform aborts.
- `length_m`, `snap_tolerance_m`, `start_offset_m`, `end_offset_m` and `qa_near_miss_m` are nonnegative finite meters. Graph edge lengths are strictly positive. Weights are QGIS measured 2D segment lengths in meters using the declared ellipsoid; for partial intervals, remeasure the clipped sequence. Cumulative path length is the sum of traversed segment weights. `snap_tolerance_m=0` permits only exact on-edge attachment. Offset uses QGIS distance measurement after finding candidates in the graph CRS.
- Canonical hash input is UTF-8 JSON with keys sorted, no extra whitespace, strings NFC, and every finite float represented by its normalized IEEE-754 binary64 `.hex()` string. Non-finite values are rejected. Hashes are SHA-256 lowercase hex. IDs use full hex with `n_` and `e_` prefixes, never truncation. Detect a collision and abort. Output numbers remain JSON numbers; float hex is for hashing only. Source identity and geometry hashes are stable only for an unchanged source snapshot, profile, transform context and QGIS behavior.
- `source_snapshot_sha256` hashes declared source CRS WKT, layer key, sorted feature keys, original complete source ordinates (including Z/M if present), multipart order, and raw values of fields selected by the rule profile. `profile_hash` hashes the canonical profile JSON. `graph_digest` hashes schema version, network CRS, source snapshot hash, profile hash, junction document hash, sorted nodes/edges/transitions and QGIS measurement metadata. No raw source URI, credentials, user name or machine path enters a public artifact. A stale digest requires rebuild/reroute; an unchanged FID never overrides a changed fingerprint.
- Any `source_native_fid` is a string diagnostic observed in one source snapshot. It is **not** a durable key. Source references for route segments are `(source_layer_key, source_feature_key, source_part_index, edge_id, from_fraction, to_fraction)` plus snapshot/graph digest. `source_part_index` is zero-based original order. Fractions are cumulative measured length along a source part, from 0 at its first vertex to 1 at its last, in original orientation. A reverse traversal has `from_fraction > to_fraction`.

## Rule profile and connection data

`RULE_PROFILE` is a local JSON document, validated strictly. Unknown top-level keys, modes, status/direction labels or rule names return `UNSUPPORTED_RULE`. There is no expression evaluator or arbitrary Python. Example:

```json
{
  "schema_version": "1.0.0",
  "profile_id": "pathways_v1",
  "connection_policy": "EXPLICIT_JUNCTIONS",
  "eligibility": {"mode": "FIELD", "field": "route_status", "map": {"available": "OPEN", "closed": "BLOCKED"}},
  "direction": {"mode": "ALL_BOTH"},
  "ellipsoid": "WGS84",
  "allow_2d_projection": false,
  "qa_near_miss_m": 1.0,
  "strict": true
}
```

`eligibility.mode` is `FIELD` or `ALL_OPEN`; `direction.mode` is `FIELD` or `ALL_BOTH`. A `FIELD` rule requires an existing string field and an exact, case-sensitive map from source string values to `OPEN|BLOCKED|UNKNOWN` or `FORWARD|REVERSE|BOTH|UNKNOWN`. Null, missing, nonstring or unmatched values become `UNKNOWN` with a QA issue and are excluded from routing. `ALL_OPEN` and `ALL_BOTH` are explicit assumptions and produce `ELIGIBILITY_ASSUMED` and `DIRECTION_ASSUMED` warnings; they never claim verified asset state. `ellipsoid` is `WGS84` or `NONE`. `NONE` uses validated planar meter measurements and is labeled `PLANAR_LENGTH`; it is not silently selected. `strict` must be `true` in v1. `allow_2d_projection=false` rejects Z/M; true discards these dimensions only after recording `Z_M_IGNORED`. `qa_near_miss_m` affects diagnostics, never connectivity. Cost weights and alternatives are absent.

For `GEOMETRIC_ENDPOINT_ONLY`, `JUNCTIONS_JSON` must be absent. Two source part endpoints connect only when normalized transformed x **and** y are exactly equal. The route's `connection_verification` is always `NOT_ASSET_VERIFIED` and the report must explain that endpoint coincidence is geometric evidence only. Interior vertices, crossings, T touches and proximity do not connect.

For `EXPLICIT_JUNCTIONS`, a `JUNCTIONS_JSON` document with the same `schema_version` is mandatory. It has `junction_crs_wkt` and a `junctions` array. Each row has a unique `junction_id`, `xy` in that CRS, at least two distinct `members`, and at least one `transitions` row. A member has unique local `member_id`, `source_layer_key`, `source_feature_key`, `source_part_index`, `segment_index` (zero-based original straight segment), and `segment_fraction` in `[0,1]` on that segment. Exactly 0 or 1 at a source vertex is canonicalized to the vertex's unique anchor; the original part start/end use `START`/`END`. A member's interpolated transformed location must **exactly** equal the declared junction point in the network CRS. Distinct members at the same coordinate remain separate unless a transition joins them. Duplicate anchors on one part, ambiguous self-intersections, inconsistent coordinates or a junction that names a missing part return `INVALID_JUNCTION`.

Each directed transition is `{ "from_member_id": "a", "from_side": "FROM_START", "to_member_id": "b", "to_side": "TO_END" }`. `FROM_START` means arrival at the junction by traveling from the source part's start side; `FROM_END` means arrival from its end side. `TO_START` or `TO_END` specifies the departure side. A side must exist at that anchor and match the eligible traversal direction. Transitions between different members are allowed only when that exact row exists; the reverse row must be declared separately. Within one source part, straight travel from one interval to the next is intrinsic and keeps its direction. Cross-part U turns and other nonlisted transitions are forbidden. A junction row is an assertion supplied by the user/data owner; the plugin labels resulting routes `DECLARED_TRANSITIONS_NOT_FIELD_VERIFIED`, never “asset verified.”

## Graph JSON and stable IDs

`network_graph.json` is one object with required `schema_version`, `kind: "NETWORK_GRAPH"`, `source_layer_key`, `source_crs_wkt`, `network_crs_wkt`, `source_snapshot_sha256`, `profile_hash`, embedded `rule_profile`, `junctions_sha256` (`null` for geometric policy), `graph_digest`, `measurement` (`ellipsoid`, `method`, `qgis_version`), sorted `source_parts`, `nodes`, `edges`, `transitions` and `qa_issues`. Every source part stores `source_layer_key`, `source_feature_key`, `source_part_index`, optional `source_native_fid`, `original_vertices`, `network_vertices_xy`, `has_z` and `has_m`. Repeated consecutive vertices are invalid because they make a zero-length source segment and ambiguous fractions. Graph readers revalidate required fields, IDs, digests, finite numbers and ordering before routing; arbitrary JSON does not become trusted internal state.

Decision D-018 records an additive, derived `build_summary` object for Tool 01. It carries `connection_policy`, `connection_verification`, `physical_edge_count`, `node_count`, `component_count`, `node_component_ids` and `source_to_edges` rows keyed by the three source-part identity fields. Its component IDs describe weak connectivity over eligible physical edges and declared transitions; they are diagnostics, not a claim of verified assets. It is excluded from `graph_digest` because it is reproducible from the graph topology. This additive metadata needs reader round-trip review before release.

The physical graph has one edge for each unsplit source part or each interval between declared anchors. Edge records contain `edge_id`, source reference, `from_node_id`, `to_node_id`, `from_anchor`, `to_anchor`, complete clipped 2D `vertices_xy`, `length_m`, `edge_status` and `direction`. It never stores an endpoint chord in place of intermediate vertices. A traversal ID is `edge_id + ":F"` or `edge_id + ":R"` and exists only if direction permits. `edge_status=BLOCKED|UNKNOWN` excludes both traversals. Public node records contain `node_id`, `xy`, kind `GEOMETRIC_ENDPOINT|PART_PORT|INTRINSIC_SPLIT`, and source anchor references. Transition records list `from_traversal_id`, `at_node_id`, `to_traversal_id`, `junction_id` and `declared: true`; intrinsic same-part continuation is marked `declared: false` and never crosses parts.

An anchor is `START`, `END`, or `{"segment_index": N, "segment_fraction": F, "junction_id": ID, "member_id": ID}`. Split anchors are sorted by original part order; identical positions are rejected unless they are the same normalized source vertex in one junction. `node_id` is `n_` plus SHA-256 of the canonical tuple `("node", schema major, network CRS WKT, policy, grouping key)`. A geometric grouping key is exact normalized network x/y float hex at a **part endpoint**. An explicit part port grouping key is the source part key plus its anchor; only intervals of the same part at the same anchor share this node. `edge_id` is `e_` plus SHA-256 of `("edge", schema major, source layer key, feature key, part index, from anchor, to anchor)`. Thus unrelated feature additions do not renumber an unchanged edge; geometry/profile changes still invalidate `graph_digest` and saved routes. IDs are compared as ASCII byte strings for deterministic sorting.

## Processing interface

The provider ID is `utilityroutelite`. `RULE_PROFILE`, `JUNCTIONS_JSON`, `GRAPH_JSON`, `RESULT_JSON`, and other `_JSON` inputs are user-selected local files. `SOURCE_LINES` and `PAIRS_LAYER` are QGIS feature sources, always read-only. The shared **source-mode group** is `SOURCE_LINES`, `SOURCE_CRS`, `NETWORK_CRS`, `LAYER_KEY`, `FEATURE_KEY_FIELD`, `RULE_PROFILE`, optional `JUNCTIONS_JSON`. Wherever `GRAPH_JSON` appears, callers supply either that graph file **or all required source-mode inputs**, never both. `GRAPH_JSON` is validated against its embedded source/config digests; an external current source can be supplied for revalidation but is not required for offline use. An output graph is an explicit path, not a hidden cache.

| Algorithm ID | Additional required/optional inputs | Required outputs |
| --- | --- | --- |
| `utilityroutelite:build_network` | Source-mode group. | `GRAPH_JSON` graph file; `QA_GPKG` issue layer. |
| `utilityroutelite:inspect_network` | Graph file or source-mode group; optional `QA_NEAR_MISS_M` override recorded in summary and affecting QA only. Source mode first scans invalid features; if they block graph construction, emit located issues with graph-dependent counts set to `null` and `analysis_complete=false`. | `QA_GPKG` (`qa_issues`); `SUMMARY_JSON` counts/policy/provenance and `analysis_complete`. |
| `utilityroutelite:find_route` | Graph file or source-mode group; `ROUTE_ID`, `START_POINT`, `END_POINT`, `REQUEST_CRS`, `SNAP_TOLERANCE_M`; optional `START_EDGE_ID`/`END_EDGE_ID` to resolve equal snap candidates. | `RESULT_JSON`; `ROUTES_GPKG` (`proposed_routes`, `route_segments`). |
| `utilityroutelite:batch_routes` | Graph file or source-mode group; exactly one of `PAIRS_CSV` or `PAIRS_LAYER`; `PAIRS_CRS`, `SNAP_TOLERANCE_M`. Input columns: `route_id,start_x,start_y,end_x,end_y`; optional `start_edge_id,end_edge_id,request_crs`. A row declaring `request_crs` different from `PAIRS_CRS` fails individually. For layer input, fields have the same names; layer CRS must equal declared `PAIRS_CRS`. | `RESULT_JSON`; `ROUTES_GPKG`; `FAILURES_CSV`. |
| `utilityroutelite:export_bundle` | `RESULT_JSON` from single or batch; optional `REVIEW_STATE_JSON`; `DESTINATION` directory or `.zip`; `OVERWRITE` explicit boolean (default false). | `BUNDLE` path, published only after complete validation. |

For `build_network`, `GRAPH_JSON` is an **output**. For the other algorithms it is an **input**. The QGIS Processing API will expose distinct parameter objects as appropriate while keeping these names. `RESULT_JSON` is an output except in `export_bundle`. Parameters use QGIS 4's Processing point/CRS, feature source, field, number, file and destination types; exact PyQGIS constructors must be checked during scaffold implementation. User cancellation never returns a successful destination. The Reviewer dock is not a Processing algorithm.

## Route result and review sidecar

`RESULT_JSON` is a versioned object with `kind: "SINGLE"|"BATCH"`, `graph_digest`, `source_snapshot_sha256`, `profile_hash`, `connection_policy`, `connection_verification`, `network_crs_wkt`, `measurement`, `requests` ordered by `input_row` and `qa_issues`. Each request records `input_row` (1-based in batch, 1 for single), nullable `route_id` if input was malformed, `requested_start_xy`, `requested_end_xy`, `snapped_start_xy`, `snapped_end_xy`, `start_offset_m`, `end_offset_m`, `status: "SUCCESS"|"FAILED"`, nullable `failure_code`, `length_m`, `qa_status`, ordered `segments` and concatenated `vertices_xy`. Coordinates/offsets may be null only when that input was invalid or could not snap. `SUCCESS` requires positive `length_m`, at least one segment and a continuous 2D route geometry. `FAILED` requires a code and has no route geometry/segments. `qa_status` is `CLEAR|WARNINGS|ERRORS`; route-associated issues determine a route's status, while global network issues remain in the result. A duplicate route ID yields row-level `DUPLICATE_ROUTE_ID`, not a second success.

Each route segment has `segment_seq` starting at 0, `edge_id`, source reference, `from_fraction`, `to_fraction`, `direction: "FORWARD"|"REVERSE"`, `length_m`, clipped `vertices_xy` and `edge_status: "OPEN"`. Every adjacent pair must meet at an authorized node/transition. A route's `length_m` is the sum of its segment lengths within documented floating tolerance; no off-network offset is added.

`review_state.json` has `schema_version`, `kind: "REVIEW_STATE"`, `result_sha256` of the canonical route result, and records keyed by route ID with `graph_digest`, `source_snapshot_sha256`, `profile_hash`, `decision: "UNREVIEWED"|"ACCEPTED_AS_PROPOSED"|"REJECTED"`, and optional note. The dock saves atomically to a user-selected destination; it cannot silently modify result JSON or source layers. A stale digest/hash blocks accepting or packaging the review. When no current source is available, the UI/report says `SOURCE_NOT_RECHECKED`. `ACCEPTED_AS_PROPOSED` is workflow review, not an engineering seal.

## GeoPackage and bundle fields

All GeoPackage geometries are 2D and use `network_crs_wkt`; the QGIS writer may add its own internal `fid`. Field names/types below are public and stable. Text keys are exact and nullability is stated. A null geometry is allowed only for `qa_issues` without a meaningful location. No source is edited to create these layers.

| Layer / WKB | Fields (SQLite type; `?` means nullable) | Row rule |
| --- | --- | --- |
| `proposed_routes` / `LINESTRING` | `schema_version TEXT`, `route_id TEXT`, `graph_digest TEXT`, `source_snapshot_sha256 TEXT`, `profile_hash TEXT`, `connection_policy TEXT`, `connection_verification TEXT`, `length_m REAL`, `start_offset_m REAL`, `end_offset_m REAL`, `qa_status TEXT`, `review_state TEXT` | One row per successful route; `route_id` unique. No fake feature for failure. Geometry contains only authorized pathway, including original intermediate vertices. |
| `route_segments` / `LINESTRING` | `schema_version TEXT`, `route_id TEXT`, `segment_seq INTEGER`, `edge_id TEXT`, `source_layer_key TEXT`, `source_feature_key TEXT`, `source_native_fid TEXT?`, `source_part_index INTEGER`, `from_fraction REAL`, `to_fraction REAL`, `direction TEXT`, `edge_status TEXT`, `length_m REAL` | One row per traversed interval; unique `(route_id, segment_seq)`; geometry matches clipped source interval. |
| `qa_issues` / `POINT` or NULL | `schema_version TEXT`, `issue_id TEXT`, `route_id TEXT?`, `severity TEXT`, `code TEXT`, `message TEXT`, `source_layer_key TEXT?`, `source_feature_key TEXT?`, `source_part_index INTEGER?`, `edge_id TEXT?`, `junction_id TEXT?` | One row per issue. `issue_id` hashes code, source ref, normalized location and occurrence. No source URI. |

`route_summary.csv` is UTF-8 with header `input_row,route_id,status,failure_code,length_m,start_offset_m,end_offset_m,qa_status,review_state,connection_verification`. It contains **all** input requests, including malformed and failed rows. Blank values represent null. Rows follow `input_row`; GeoPackage successful routes follow `(route_id, segment_seq)` byte order. `FAILURES_CSV` uses `input_row,route_id,code,reason` and contains every failed batch row, including rows with a blank/duplicate route ID. For cells starting with `=`, `+`, `-`, or `@` after leading whitespace/control characters, prefix an apostrophe before RFC 4180 quoting. This applies to every user-controlled cell, including IDs and notes. HTML content is escaped for text/attribute context, and report links are local allowlisted filenames only.

`routing_config.json` includes `schema_version`, `kind: "ROUTING_CONFIG"`, profile and its hash, connection policy/verification, source snapshot hash, graph digest, CRS/measurement metadata, counts, supported/ignored dimensionality warnings, `source_verification: "SNAPSHOT_ONLY"|"CURRENT_SOURCE_MATCHED"`, and SHA-256 of the other bundle files. The packager validates all inputs and review hashes, writes `utility_routes.gpkg`, `route_summary.csv`, `report.html`, and then this config manifest in a staging directory. It publishes the complete directory or ZIP only after all files close and validate. Existing destinations require `OVERWRITE=true`; refusal or error leaves the prior destination intact. This is content-deterministic reporting; byte-identical GeoPackage/ZIP creation across hosts is not promised without a separate reproducibility test.

## Error codes and compatibility

Stable expected request failure codes: `NO_ROUTE`, `OUTSIDE_SNAP_TOLERANCE`, `AMBIGUOUS_SNAP`, `BLOCKED_EDGE`, `UNKNOWN_ELIGIBILITY`, `FORBIDDEN_TRANSITION`, `SAME_LOCATION`, `INVALID_PAIR`, `DUPLICATE_ROUTE_ID`. Build/job errors: `INVALID_CRS`, `TRANSFORM_FAILED`, `INVALID_GEOMETRY`, `UNSUPPORTED_DIMENSION`, `UNSUPPORTED_RULE`, `INVALID_JUNCTION`, `DUPLICATE_SOURCE_KEY`, `ID_COLLISION`, `STALE_GRAPH`, `STALE_REVIEW`, `LIMIT_EXCEEDED`, `CANCELED`, `EXPORT_FAILED`. Baseline QA codes are `UNDECLARED_CROSSING`, `INTERIOR_TOUCH`, `NEAR_MISS`, `OVERLAP`, `DANGLE`, `DISCONNECTED_COMPONENT`, `INVALID_GEOMETRY`, `UNKNOWN_ELIGIBILITY`, `UNKNOWN_DIRECTION`, `ELIGIBILITY_ASSUMED`, `DIRECTION_ASSUMED`, `Z_M_IGNORED`, and `SOURCE_NOT_RECHECKED`. User-facing messages add context; programs rely on codes. An unknown or blocked edge may produce `NO_ROUTE` with a subordinate excluded-edge issue, but it must never be traversed. All required fields and enums are listed in the machine registry.

A reader accepts `1.x` only when it recognizes all required fields and can safely ignore added optional **output metadata**; it rejects unknown enum values and major versions. Rule profiles and junction documents are stricter: unknown keys that might change connectivity or eligibility remain `UNSUPPORTED_RULE` until that reader explicitly implements the new minor version. A writer stays at `1.0.0` until the new version has schema migration and round-trip tests. Review state cannot be reused when result or graph digest changes. Algorithm IDs and parameter names must remain stable through v1; deprecations require a decision, migration instructions and a compatibility test. A minor version may add optional output fields but cannot make an optional constraint silently mandatory or change routing semantics. The architecture stage is complete as a **specified interface** once registry validation passes; functional compliance begins with the scaffold/fixtures stages.

Round 2 clarification (D-019): `ID_COLLISION` aborts on conflicting node identity payloads or duplicate edge IDs; no graph is published. D-020: arbitrary CRS definitions are validated by PyQGIS, not parsed by the graph core. The core can use known `EPSG:3857` synthetic meter coordinates without QGIS. Other CRS forms, including full WKT, require the installed QGIS runtime; absent that validator they fail `INVALID_CRS`. Supplying a transform requires a measurement callback and never bypasses target-CRS validation. Existing QGIS source adapters provide both.
